# 真需求与求真门

在需求讨论、从 0 到 1、新功能、重大扩展或关键前提缺少证据时使用。目标不是发现一个永恒不变的“隐藏需求”，而是判断：当前具体场景中，什么已经被现实支持，什么只是合理猜测，什么值得下注验证。

## 1. 基本立场

- 价值不能由供给方自我宣布；必须落在具体对象的需要与选择上。
- 真需求不是单向迎合。对方的需要、我方的需要与双方关系都要诚实可见。
- 口头赞同、礼貌夸奖和访谈兴趣是弱信号；真实行为、资源投入和持续选择通常更强。
- 真实需要可以伴随吐槽和不满；满意不等于需要，不满也不自动否定需要。
- 创新最初可能没有共识。证据不足不等于否决，只意味着不能伪称已经验证。
- 需求会随场景、供给、基础设施和时代变化；每个结论都说明适用条件。

## 2. 现实镜：先分清在谈什么

把用户输入在内部归入五类：

| 类型 | 判断 |
|---|---|
| 实然 | 已观察到的行为、结果、事件、约束和一手材料 |
| 解释 | 对事实为何发生的因果判断 |
| 应然 | 认为用户、市场或组织应该怎样 |
| 偏好/意图 | 主体愿意主动选择的方向，不必伪装成外部需求 |
| 解法 | 为目标预设的功能、流程、产品或商业形态 |

只向用户说明会改变决定的差距。例如，商户领取过物料可以支持领取意愿；要判断真实使用，需查看摆放和持续使用的记录。能从授权材料里核对就先核对。

## 3. 把需求落到具体场景

使用这个表达检查颗粒度：

> 当 [具体角色] 在 [触发与环境] 中想完成 [进展] 时，目前会 [替代行为]，即使要承担 [时间/金钱/风险/情绪/组织成本]；若获得 [核心价值]，他愿意用 [可观察承诺] 交换。

缺少具体角色、触发、替代、代价或承诺时，优先从现有材料还原最近一次真实事件。材料无法回答时，给出条件判断、可执行的验证，或询问只能由用户提供的事实。

按需检查：

- 最近一次真实事件是什么，而不是一般而言会怎样；
- 当前替代为什么能存活，它保护了什么；
- 什么都不做的真实后果是什么；
- 用户请求的是目标，还是他能想到的解法；
- 价值主要是功能、情绪、资产，还是几者组合；
- 哪个价值消失后，用户仍会无所谓。

## 4. 三道门

| 门 | 核心问题 | 常见反证 |
|---|---|---|
| 价值 | 对方在该场景为什么需要我们，而不是“这个东西很好”？ | 没有替代成本；场景过泛；只有供给方自我评价 |
| 共识 | 哪些人必须支持，他们会用什么行动、资源或风险承诺？ | 只有赞美；使用者、付款者、审批者互相冲突 |
| 模式 | 我方为什么做，靠什么能力持续交付并换回所需资源？ | 依赖长期补贴、英雄式运营或不存在的能力 |

共识证据按场景解释：

- 商业产品可看付费、续费、复购、切换与推荐；
- 内部产品可看预算、流程迁移、责任人承诺、持续采用；
- 公共或合规事项可看资源配置、审批、执行覆盖与结果改善；
- 任何场景都不要把“用户说喜欢”直接当作需求已成立。

涉及新技术或新市场时，再检查场景成熟度：业务是否成立、数据是否可得、技术是否够用、运营是否承接、监管是否允许。方向正确但场景未成熟，也可能在当前失败。

## 5. 证据强度

从多个角度组合证据，不机械打分：

1. **陈述**：投诉、访谈、问卷、销售反馈；
2. **行为**：现有替代、人工补救、绕路、重复尝试；
3. **承诺**：投入金钱、时间、数据、声誉、预算或改变流程；
4. **持续结果**：留存、复用、续约、稳定履约或可重复改善；
5. **反证**：不采用、快速流失、绕开功能、拒绝承担代价。

记录证据日期、样本边界和来源。没有证据写“未验证”，不要写“需求不存在”。

## 6. Agent 的反顺从行为

在以下情况主动挑战：

- 用户从“我想做 X”直接跳到“用户需要 X”；
- 目标人群是“所有人”“大多数商户”等宽泛对象；
- 只有意见、赞美或竞品功能，没有真实行为；
- 解法与目标、现有领域模型或已知事实冲突；
- 用户价值成立，但我方能力、回报或安全边界不成立；
- 多方关系中遗漏付款、审批、执行、供给或责任角色；
- 高代价、难逆决策建立在单一案例或过时事实上。

挑战前提，不挑战人格。说清：

1. 当前把什么假设成了事实；
2. 哪条现实证据支持或反对；
3. 如果判断错了会损失什么；
4. 用什么最小行动可以更接近真相。

一次优先挑战一个最关键前提。用户已理解边界并选择继续时，把它记为战略下注，不以“求真”为名持续阻挠。

## 7. 决策动因与逐项证据

先说明为什么做。例如客户需要、经营目标、战略选择、合规义务或品牌偏好可以同时存在。已经拍板的动因直接沿用，并写清其来源。动因本身不会证明某类客户愿意采用或付费。

再对**会改变决定的每一项假设**分别判断。引用对应记录和适用场景：

| 证据状态 | 判断依据 |
|---|---|
| 有支持 | 已观察到与这项主张直接对应的行为、约束或结果。说明它支持到什么程度。 |
| 待验证 | 缺少能区分几种解释的观察。写清最便宜的取证方法，以及什么结果会改变建议。 |
| 有反证 | 某项实际选择或结果与预期冲突。说明冲突发生在哪个样本、环节或条件下。 |

证据有分歧时同时呈现支持与反证，必要时按人群或条件拆开。例如“公司决定试水”是动因，“有人试用”“多次使用”“愿意按报价付费”需要各自的证据。试用日志只能回答其中相应的问题。

最后给出下一步建议，例如推进、缩小范围试验、暂缓或停止，并解释哪项证据决定了它。只问值不值得做时，到这个判断即可。需要试验时写出能区分支持与反对的判据；用户已授权推演或改稿时，按已知边界继续。

## 8. 最小求真试验

只验证最可能推翻方案的假设：

- 假设：必须具体、可证伪；
- 探针：访谈之外，尽量包含真实任务或承诺；
- 支持信号：出现什么才增加信心；
- 反对信号：出现什么必须修改或停止；
- 成本与期限：用最小可逆投入获取信息；
- 决策规则：继续、调整、收缩或停止。

失败是现实反馈，不用包装成成功。试验无论结果如何，都应减少关键未知。

### 常见试验模式

根据要验证的假设类型选择：

| 模式 | 适用场景 | 做法 | 判断信号 |
|---|---|---|---|
| 意图测试 | 不确定对方是否真的想要 | 用着陆页、预约表单或价格锚点收集真实意向行动 | 留资率、到店转化、价格敏感度 |
| Wizard of Oz | 不确定服务流程能否跑通 | 前台看似产品化，后台人工完成关键环节 | 完成率、满意度、人工成本是否可控 |
| 替代切换 | 不确定对方是否愿意从现有方案迁移 | 在真实场景中提供新方案与旧方案的并行选择 | 主动切换比例、切换后留存、回退率 |
| 承诺探针 | 不确定口头认可是否转化为行动 | 要求对方投入时间、预算、数据或流程变更 | 是否兑现承诺、兑现速度与完整度 |
| 最小闭环 | 不确定端到端价值能否成立 | 用最少功能跑完一次从触发到结果的完整流程 | 流程是否走通、用户是否确认获得了价值 |

选择时优先覆盖「如果这个假设错了，整个方案不成立」的那个。一个试验只验证一个核心假设，不要把试验变成 MVP 发布。

## 9. 反模式

- 一上来给出整套问卷，让讨论变成审讯；
- 把付款当作所有场景唯一证据；
- 因没有历史行为就否定潜在需求和创新；
- 把用户所有抱怨都变成功能需求；
- 核心需求未证实，却直接写出完整 PRD、产品规则和精确指标；
- 用精美方案掩盖没有场景、没有承诺、没有模式；
- 没有读取来源，却声称沿用了既有决定、边界或当前实现；
- Agent 把自己的推断当真相，借“反顺从”夺走用户决策权。
